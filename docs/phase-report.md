## 1. What was built

```

  database.py             SQLAlchemy engine/session
  auth.py                 PBKDF2 hashing + HMAC-signed tokens (stdlib only)

  schemas/domain.py       RecoveryContext, AgentResult, PolicySpec, plan contracts
  agents/                 discount, inter_store_swap, buy_a_get_b, b2b_bulk_buyer

                          guardrail, execution, verification, audit, data_ingest

  seed/seed.py            deterministic 252-product demo dataset with 5 scenarios
```

### Frontend (`frontend/`)
Next.js 14 App Router + TypeScript + Tailwind + Recharts. Seven screens: Login, Dashboard,
Dead Stock Center, Product Detail, Recovery Studio, Store Network, B2B Market, Action History.
Dark industrial theme on `#0B0F17` with `#00F2FE` / `#4FACFE` accents, green/amber/red signal
colours.

### Infrastructure
`docker-compose.yml` (Postgres 16 + backend + frontend), `docker/backend.Dockerfile`,
`docker/frontend.Dockerfile`, `.env.example`, `Makefile`, Alembic, Playwright config.

The sandbox has **no Docker and no PostgreSQL**, so database-backed runtime was validated on a
scratch SQLite database (the code targets Postgres; SQLite is only a test substitute).

* `python -m app.seed.seed` → 252 products, 103,681 sales rows, 663 inventory rows, 7 buyers, 2 users.
* Forecast warm-up on all 663 inventory rows (real XGBoost training) — 239 s.
* Full `analysis → agents → plan → guardrails → execution → verification` on a seeded
  dead-stock SKU produced a real plan and cleared 156 units, with a `prototype_simulation`

## 3. Errors found and fixed

| # | Error | Root cause | Fix |
|---|---|---|---|
| 1 | `MappedAnnotationError` on `Mapped[list]` / `Mapped[dict]` | SQLAlchemy cannot infer a column type for bare `list`/`dict` | Declared `JSON` explicitly on every such column |
| 2 | `ValidationError: days_since_sale missing` | `compute_metrics` passed `days_since_last_sale` while the schema field is `days_since_sale` | Corrected field names on both sides |
| 3 | `TypeError: cannot unpack non-iterable Inventory` | `db.scalars()` on a two-entity `select(Inventory, Store)` returns one column | Switched to `db.execute(...).all()` in `_peer_stores` and `_bundle_candidates` |
| 4 | `AttributeError: PolicySpec has no attribute …` | The agent-facing policy contract was missing fields the agents read | Added `max_anchor_candidates`, `hybrid_weight_steps`, `hybrid_min_improvement` and mapped them |
| 5 | `GET /api/dashboard` returned 200 without a token | Dashboard routes never depended on `current_user` | Added the dependency; the test now asserts 401 |
| 6 | Forecast warm-up was ~4× slower than needed | The path walk ran once per horizon | Single calendar pass recording cumulative totals per horizon |
| 7 | 98% of seeded SKUs were flagged dead stock | Forecast was absent for un-warmed rows (ratio → ∞), **and** low-stock fast sellers were flagged when merely old | Made low stock suppress candidacy outright; tuned seed stock/age ranges |
| 8 | Route shadowing: `/stores/transfer-opportunities` was matched by `/stores/{id}` | Declaration order | Moved the literal route ahead of the parameterised one (and renamed the detail route) |
| 9 | `pytest` could not write `.pytest_cache` on the network mount | S3-backed FS rejects the rename | `-p no:cacheprovider` in `pytest.ini` |

## 4. Design decisions worth flagging

* **Net recovery, not revenue.** Every option is scored as
  `recovery − action cost − friction − risk penalty`, with coefficients in `app/config.py`.
* **Hybrid only when it strictly wins.** A hybrid plan is kept only if it beats the best single
  strategy by `HYBRID_MIN_IMPROVEMENT` (3%), and it can never allocate a unit twice.
* **Low stock is never dead stock.** Enforced in `is_recovery_candidate` and covered by a test.
* **Agents are pure and crash-isolated.** They receive a `RecoveryContext`, never the ORM, and an
  agent failure degrades to `feasible=False` rather than failing the request.
* **Verification is labelled.** Every simulated outcome row carries
  `label = "prototype_simulation"` and the UI repeats it.

## 5. Known limitations / not yet done

1. **This sandbox cannot run the stack.** No Docker daemon and no PostgreSQL server here, so
   `docker compose up`, the Next.js build and Playwright were **not** executed in-environment.
   Backend logic is verified by the pytest suite and the SQLite validation above; the frontend is
   written to type-check but `tsc --noEmit` has not been run (installing `node_modules` on the
   network-mounted filesystem is not viable).
2. **Seed warm-up is slow** (~4 minutes for 663 forecasts, XGBoost trained twice per SKU:
   holdout + final refit). Acceptable one-time cost; the `--skip-forecast` flag exists for speed.
3. **`ACTION_RESULT` uses a fixed ±6% deterministic spread** for the simulated realisation. It is
   reproducible and honestly labelled, but it is a simulation, not measurement.
4. **Remaining gaps**: no frontend unit tests (only Playwright end-to-end specs, unexecuted
   here), no CI pipeline, and no real POS/marketplace connectors (interfaces are mock-shaped).
5. **Optional LLM narration is not wired.** The explanation text is generated deterministically
   from real values; `LLM_API_KEY` is reserved for a later pass.
